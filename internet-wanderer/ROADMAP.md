# Roadmap

当前版本为 **0.3.0 UI Demo**。四个入口、三种模式、年代主题、最近遇见、本机收藏及 JSON 导入／导出已实现。默认使用静态内容与固定样本时间，重点是让用户随时打开就能体验完整漫游循环。

## 本轮已完成

- 四入口、三个模式与年代主题完成；新增手工明信片、报刊刊头和年代字体／控件／动效。
- 手机固定操作栏、出发／到达反馈、键盘连续换站、浏览器返回及整组时光卡片恢复完成。
- 配置驱动的年代注册与统一内容提供接口完成，支持加载取消和重试，继续使用静态数据。
- 收藏、备份与 Demo／Live 时钟收尾；构建、55 项逻辑测试和 30 项浏览器测试通过。
- 直接 hash 导航问题已修复；桌面及 320px／390px 小屏、焦点与减少动画通过检查。
- 截图和完整源码交付包提供本地运行说明，详见 [验收记录](docs/UI_DEMO_REVIEW.md)。

## 当前阶段：体验反馈

- 邀请 3～5 人各体验约 10 分钟，观察愿意打开的条目、退出原因、是否找得到上一站，以及收藏与备份是否容易理解。
- 抽查外站与三个档案快照；确认失效后先禁用或替换，不用一次超时推断永久失效。

## 下一步候选：先解决真实体验问题

- 根据体验反馈进一步改善内容选择与排版，保留清晰的主动作；本轮手机操作栏与换站反馈已完成。
- 维护少量更有差异的网站和年份内容；每个年份继续提供事件、去处与真实档案依据。
- 增加经过审核的非英语内容，准确标注来源语言与所在地。
- 改善收藏较多时的浏览体验与迁移说明，沿用现有 500 条／1 MiB 上限、合并去重和原数据保护。
- 需要分享时再添加稳定的站内条目链接，并处理快照不存在或新闻到期的情况。
- 需要公开演示时部署静态 `dist/` 并验证仓库子路径；Demo 发布无需先启动定时采集。

这些是候选事项，不是同时交付的承诺。选择用户反馈反复出现的问题，避免为增加功能破坏漫游节奏。

## 数据联调阶段：另行推进

真实 API、数据库、RSS 联调、自动 Archive 查询／接入都留待后续。已有 RSS adapter、快照和 Pages 工作流保留，当前 UI 不依赖这些远程服务运行。

开始下一阶段时，应先明确需要改善什么：更新频率、内容覆盖还是维护成本，再接入合适的来源。继续通过统一内容边界输出 `WanderItem`，保持 BrowserFrame、主题、选择算法、hook 和动效分离。

- 重新核对官方 feed、API 条款与允许展示的字段，保留作者及许可要求。
- 启用 Live 后验证真实 48 小时来源新鲜度、7 天文章有效期、单源失败保留和全空降级。
- 如以后增加 GitHub 定时更新，先明确启用范围，再验证 Pages 配置、来源访问、快照保存策略和计划任务运行情况；当前发布工作流默认仅构建静态 Demo。
- 自动档案接入必须确认精确捕获时间与实际内容，不能把查询目标日期当作捕获日期。
- 只有跨设备同步或多作者维护需求成立后，再评估账号、数据库和服务端存储。

## 明确推迟

任意年份／日期自动生成、完整旧互联网复刻、全文采集与翻译、用户画像与精准推荐、复杂分类筛选、CMS、支付、社区投稿和云端收藏均不属于当前 Demo 范围。当前没有引入 Supabase、Redis、向量检索或运行时爬虫的需要。

维护优先保证稳定 ID、真实日期、可追溯署名、收藏原数据保护，以及内容不足时仍能继续漫游。
